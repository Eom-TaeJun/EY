# EY FSRM Requirement-to-Evidence Map

## Status vocabulary

| Status | Meaning | Numerical use |
|---|---|---|
| Implemented | deterministic producer or control exists | no numerical claim |
| Pending evidence | producer exists but required run evidence is missing/failed | no numerical claim |
| Validated | independent run evidence and required Gate contract pass | internal claim only |
| Gate 5 passed | cross-artifact values and run identity reconcile | awaiting human publication decision |
| Externally approved | Gate 5 passed and a human approved publication | may be quoted with run ID and limitations |
| Blocked | known failure or missing prerequisite | no numerical claim |

No row below is automatically promoted by editing this document. A run-specific
claim manifest generated by `src.reporting.build_wave1_report` supplies the run
ID and JSON evidence pointers; the Orchestrator/Reviewer records Gate status.

## Claim-to-source path

Every activated numerical claim must retain this path:

`claim ID → run-specific claim manifest → independent validation JSON → Gate
check → deterministic SQL/code → mart/core → staging rule → raw row → source
file and SHA-256`.

Broken or mixed-run paths are `Blocked`. Missing evidence is never interpreted
as zero, pass, or not applicable.
